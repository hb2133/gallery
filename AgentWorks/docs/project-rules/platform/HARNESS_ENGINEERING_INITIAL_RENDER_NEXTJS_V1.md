# HARNESS ENGINEERING (Persisted Initial Render, Next.js) V1

## 1) 목적

Supabase, 인증 세션, 쿠키, 로컬 저장소 등에서 불러오는 사용자 설정 기능이
새로고침 첫 화면에서 임시 기본값을 노출하지 않도록 구현·검증 기준을 고정한다.

이 규칙은 앞으로 추가하거나 수정하는 모든 기능에 적용한다.

## 2) 핵심 불변 조건

- 서버 첫 HTML, hydration 직후 DOM, 클라이언트 동기화 이후 DOM은 같은 저장 설정을 표현해야 한다.
- 저장된 값이 있는데 정적 기본값을 먼저 렌더링한 뒤 `useEffect`에서 교체하는 구현을 금지한다.
- 인증 여부에 따라 보이는 UI도 서버 첫 렌더링과 hydration에서 일치해야 한다.
- 실제 값을 서버에서 구할 수 없을 때 잘못된 기본값을 보여주지 않는다.
  필요하면 의미가 중립적인 로딩 상태를 사용하되 레이아웃 이동을 최소화한다.

## 3) 기능 구현 전 필수 설계

새 기능을 구현하기 전에 아래 항목을 작업 문서에 기록한다.

1. 첫 화면에 영향을 주는 저장값이 무엇인지 식별한다.
2. 값의 SSOT가 Supabase, 쿠키, 로컬 저장소 중 어디인지 정한다.
3. 서버에서 읽을 수 있는 공유 설정은 Server Component 또는 서버 초기 상태 Manager에서 읽는다.
4. 초기 상태를 Client Provider 또는 BasePanel 입력으로 직렬화한다.
5. Client Controller의 최초 state는 전달받은 서버 초기값으로 생성한다.
6. 브라우저 재조회는 최초 표시가 아니라 최신 상태 동기화 용도로만 사용한다.
7. 저장 작업이 끝나면 로컬 state와 SSOT를 함께 갱신하고 다음 서버 요청에서도 같은 값이 반환되게 한다.

## 4) 구현 규칙

### 4-1) 서버에서 읽을 수 있는 값

- 공개 설정과 인증 설정은 가능한 한 서버에서 병렬 조회한다.
- 서버 조회 결과를 앱 초기 상태 타입에 명시적으로 포함한다.
- 기본값은 DB 행이 없거나 값이 유효하지 않은 경우에만 fallback으로 사용한다.
- Client Component에서 동일 데이터를 다시 불러오더라도 서버 초기값과 같은 형태로 normalize한다.

### 4-2) 브라우저에서만 읽을 수 있는 값

- 테마처럼 첫 paint 전에 필요한 값은 hydration 이전 bootstrap script, 쿠키 또는 서버가 읽을 수 있는 상태로 승격한다.
- `useEffect`만으로 첫 화면의 색상, 문구, 이미지, 레이아웃을 뒤늦게 교체하지 않는다.
- 브라우저 전용 값이 준비되기 전에는 반대 상태나 임의 기본 문구를 노출하지 않는다.

### 4-3) 관계 데이터

- 카테고리와 카드처럼 서로 참조하는 저장 설정은 같은 초기 snapshot에서 파생한다.
- 참조 대상이 삭제된 경우의 표시 규칙을 명시한다.
- 서버와 클라이언트에서 동일한 normalize·fallback 규칙을 사용한다.

## 5) 금지 패턴

- 정적 기본값으로 `useState`를 만든 뒤 mount 후 원격 값으로 교체
- 저장된 링크 대신 기본 링크, 저장 이미지 대신 샘플 이미지, 실제 인증 UI 대신 비로그인 UI를 먼저 표시
- 깜빡임을 숨기기 위해 임의 timeout이나 불투명도 지연을 추가
- 서버 normalize와 클라이언트 normalize가 달라 hydration 결과가 바뀌는 구조
- 새 저장 기능을 추가하면서 앱 초기 상태 계약과 새로고침 검증을 생략

## 6) 필수 검증 하네스

저장 기능을 완료하기 전에 다음을 확인한다.

1. 기본값과 명확히 다른 테스트 설정을 저장한다.
2. 해당 route의 서버 첫 HTML을 직접 요청한다.
3. 첫 HTML에 저장된 카테고리, 문구, 이미지 URL 또는 안정적인 식별자가 포함됐는지 확인한다.
4. 첫 HTML에 대체되는 기본값의 식별자가 포함되지 않았는지 확인한다.
5. hydration 전후 화면이 같은 상태인지 확인한다.
6. 느린 네트워크에서도 잘못된 기본값이 먼저 나타나지 않는지 확인한다.
7. 로그인·비로그인 양쪽에서 권한 UI의 첫 렌더링이 맞는지 확인한다.
8. `npx tsc --noEmit`, `npm run lint`, `npm run build`를 실행한다.

## 7) 리뷰 판정

- 새 저장 기능에 서버 초기 상태 또는 동등한 첫 paint 전략이 없으면 완료로 판정하지 않는다.
- 실제 비기본 저장값을 사용한 첫 HTML 검증 근거가 없으면 `ReadyToCommit: yes`로 변경하지 않는다.
- 기본값 노출, hydration 교체, 권한 UI 지연 노출이 재현되면 회귀 버그로 분류한다.

## 8) 현재 프로젝트 기준 구현 경로

- 서버 초기 상태: `src/managers/InitialAppStateManager.ts`
- Client 초기 상태 Provider: `src/app/shell/InitialAppStateProvider.tsx`
- 인증 초기 상태: `src/app/shell/AuthSessionProvider.tsx`
- Supabase 서버 client: `src/core/infra/supabase/SupabaseServerClient.ts`

새 설정 기능은 특별한 이유가 없는 한 위 초기 상태 흐름을 확장한다.
