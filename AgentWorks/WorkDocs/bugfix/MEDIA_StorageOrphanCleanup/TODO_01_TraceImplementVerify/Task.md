# Task

## Context
- 관리자가 이미지나 게시글을 교체·삭제해도 이전 객체가 Storage에 계속 남는다.

## Current Understanding
- DB 변경과 Storage 객체 삭제는 자동 연동되지 않아 애플리케이션에서 성공 후 정리해야 한다.
- 공유 URL이 다른 활성 게시물에서도 쓰일 수 있으므로 현재 DB 참조를 다시 확인한 뒤 삭제해야 한다.

## Observed Issues
- 원격 Storage에서 미참조 객체 48개, 61.39MiB를 확인했다.

## Decision Notes
- 원본 해상도와 알파를 보존하기 위해 자동 축소·WebP 변환은 적용하지 않았다.
- DB 저장이 성공하기 전에 기존 파일을 삭제하지 않는다.
- 프로젝트·버킷 소유권과 활성 참조를 확인할 수 없으면 삭제하지 않는다.

## Initial Render Harness
- 표시 데이터의 SSOT와 서버 초기 상태는 변경하지 않았다.
- 정리는 저장 성공 뒤 실행되며 활성 URL은 유지된다.

## Fix Notes
- 메인 이미지, Gallery 본문·썸네일, Writing 표지의 교체·삭제 정리를 추가했다.
- 저장 실패로 새로 생긴 업로드도 참조가 없을 때 제거한다.
- 외부 URL과 `/images` 정적 파일은 삭제 대상에서 제외한다.

## Result
- 원격 미참조 객체 48개, 61.39MiB를 삭제했다.
- 정리 후 남은 객체 44개와 활성 참조 44개가 일치했다.
- 미참조 객체 0개, 누락된 활성 참조 0개를 확인했다.
- URL 파서 테스트, ESLint, TypeScript, 프로덕션 빌드를 통과했다.

## History Index
- 아직 분리된 이력이 없다.
