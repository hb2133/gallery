# Task

## Context
- 긴글 작성 흐름을 끊지 않고 구분선과 목록을 만들고, 미디어 블록을 가로로 조합하거나 정렬할 수 있어야 한다.

## Current Understanding
- 현재 native `contentEditable`과 `execCommand` 경로가 슬래시 명령 및 목록을 이미 처리한다.
- 저장 HTML의 `figure` 폭을 유지하면서 표시 방식만 inline-block으로 바꾸면 크기를 줄인 연속 미디어는 새 레이아웃 모델 없이 나란히 놓인다.
- `figure[data-align]`만 저장 허용하면 이미지와 영상이 같은 정렬 계약을 공유한다.

## Observed Issues
- 현재 figure가 항상 block과 100% 폭으로 시작해 크기를 줄여도 다음 figure가 옆에 오지 않는다.
- 목록의 Tab 키는 편집기 밖으로 포커스를 이동시킨다.
- 왼쪽 정렬을 선택하면 figure가 다시 block이 되어 축소된 연속 미디어도 같은 줄에 놓이지 않았다.
- 같은 줄 미디어 한쪽의 폭만 바뀌어 옆 미디어가 다음 줄로 밀렸고, 드래그 중 좌우 배치 위치와 간격 상태가 보이지 않았다.
- 나란히 배치한 미디어를 가운데 정렬해도 같은 줄 간격 규칙이 남았고, 미디어를 다시 독립 줄로 꺼낼 드롭 위치가 없었다.
- 코드 블록의 Enter/Shift+Enter 동작이 의도와 반대였고 코드가 본문과 같은 시각 스타일이었다.
- 슬래시 검색이 공백을 그대로 비교해 `/제목1`로 `제목 1`을 찾지 못했다.

## Decision Notes
- 새 블록 편집기 의존성 없이 기존 브라우저 명령, HTML 정화, CSS를 확장한다.

## Initial Render Harness
- 정렬값은 기존 `writing_posts.content_html`의 `figure[data-align]`에 저장한다.
- `InitialAppStateManager`가 정화된 저장 HTML을 서버에서 읽는 기존 흐름을 유지하므로 첫 HTML과 hydration이 같은 정렬을 사용한다.

## Implementation Notes
- `/구분선`과 `---` 입력을 기존 `insertHorizontalRule` 명령에 연결했다.
- `- `와 `1. `는 현재 블록 전체가 입력 기호일 때만 native 목록으로 변환한다.
- 목록 항목의 Tab/Shift+Tab을 indent/outdent에 연결하고 중첩 번호 목록은 영문 소문자로 표시한다.
- figure를 inline-block으로 표시해 저장 폭의 합이 편집 폭보다 작으면 연속 미디어가 나란히 배치된다.
- 선택한 figure의 정렬 메뉴가 `data-align`을 갱신하고 저장 정화가 해당 속성을 보존한다.
- 왼쪽 정렬도 inline-block을 유지하고 `나란히`는 선택 미디어와 바로 옆 미디어를 각각 48% 폭으로 맞춘다.
- 미디어를 다른 미디어 좌우로 드래그하면 파란 배치선과 위치 문구를 표시하고 drop 시 같은 줄로 이동한다.
- 같은 줄의 안쪽 리사이즈 핸들은 두 미디어 폭을 반대로 조절해 줄바꿈 없이 전체 폭을 유지한다.
- 미디어 메뉴의 간격 선택으로 없음, 좁게, 보통 값을 저장한다.
- 왼쪽·가운데·오른쪽 정렬 시 같은 줄 연결을 해제하고 짝 미디어 폭을 복구하며, 빈 편집 영역 드롭으로 미디어를 새 줄에 꺼낼 수 있게 했다.
- 선택한 미디어의 좌우 크기 조절 손잡이를 검은색으로 바꿨다.
- 선택한 미디어의 파란 외곽선을 제거하고 검은 크기 조절 손잡이만 표시한다.
- 텍스트 선택 메뉴나 미디어 편집 메뉴가 열려 있는 동안 wheel·touchmove 기본 스크롤을 잠근다.
- 코드 블록은 Enter가 내부 줄바꿈, Shift+Enter가 본문 문단으로 빠져나가도록 바꾸고 작은 모노스페이스 다크 코드 스타일을 적용했다.
- 슬래시 검색어와 명령 라벨·설명의 모든 공백을 제거한 뒤 비교해 공백 유무와 관계없이 같은 스타일을 찾는다.

## Result
- 입력 단축어·슬래시 공백 정규화·코드 Enter 동작 단위 테스트 5개, TypeScript, ESLint, 프로덕션 빌드가 통과했다.
- `http://192.168.0.41:3000/writing`이 HTTP 200으로 응답했다.
- 왼쪽 정렬의 block 충돌을 제거하고 연속 미디어 `나란히` 48% 배치를 추가한 뒤 빌드와 새 개발 번들을 재검증했다.
- 좌우 drag feedback, 공유 resize, 저장형 간격 메뉴를 추가한 뒤 단위 테스트, TypeScript, ESLint, 프로덕션 빌드를 재검증했다.
- 나란히 배치 해제·새 줄 드롭, 검은 resize 손잡이, 코드 블록 키 동작·스타일, 공백 없는 슬래시 검색을 추가하고 자동 검증을 재통과했다.
- 개발 서버를 새 번들로 재시작해 `/writing` HTTP 200과 최신 UI 문자열이 개발 청크에 포함된 것을 확인했다.
- 인증 브라우저 상호작용과 실제 비기본 저장값의 서버 첫 HTML 확인은 남아 있다.
