# Task

## Context
- 시작 페이지 커서가 기본 브라우저 커서이며 호버 대상 정보가 없다.
- 카테고리 선택 후 나타나는 다섯 박스의 위치가 CSS에 고정되어 관리자 변경이 불가능하다.

## Current Understanding
- 커서는 시작 페이지 전용 시각 조각으로 두고 포인터 이동 시 위치와 `data-cursor-label`을 읽는다.
- 박스 배치는 중앙 13번 셀을 고정하고 5×5 영역에서 네 칸을 추가 선택하는 카테고리별 설정으로 저장한다.
- 기존 `StartPageCustomization` 서버 초기 상태 흐름을 확장한다.

## Observed Issues
- 기존 박스 마스크와 이동 위치가 카테고리별 CSS 선택자에 중복되어 있다.
- 현재 이미지 레이어는 선택 해제와 동시에 제거되어 퇴장 애니메이션이 없다.

## Decision Notes
- 25칸 전체를 자유 선택하되 레퍼런스와 현재 중앙 상호작용을 유지하기 위해 중앙 13번은 고정한다.
- 별도 캔버스나 애니메이션 의존성 없이 CSS 변수와 순차 keyframe을 사용한다.

## Initial Render Harness
- 저장값: 카테고리별 다섯 박스 셀 번호 배열.
- SSOT: Supabase `start_page_settings.category_box_layouts`.
- 서버의 `InitialAppStateManager`가 정규화해 Provider로 직렬화하고 Controller 최초 state가 그대로 사용한다.
- 브라우저 재조회는 최신 상태 동기화에만 사용한다.

## Implementation Notes
- 시작 화면 전용 커서가 헤더와 Hero에서 포인터를 따라가며 `data-cursor-label`의 대상 이름을 표시한다.
- 관리자 카테고리 카드의 `박스 위치 설정`을 누르면 설정창을 닫고 메인 Hero를 5×5 편집판으로 전환한다.
- 메인 Hero의 네 박스를 빈 칸으로 드래그해 이동하며, 클릭으로 박스와 목적지를 차례로 선택하는 키보드·터치 대체 동작도 제공한다.
- 중앙 13번 박스와 이미 사용 중인 칸은 이동 대상으로 사용할 수 없고, 설정창으로 돌아가 기존 저장 버튼으로 확정한다.
- 카테고리별 셀 배열을 Supabase, 서버 초기 상태, 브라우저 캐시와 저장 요청에 연결했다.
- 이미지 타일과 게시판 버튼은 순차적으로 중앙에서 펼쳐지고 선택 해제 시 역순으로 모인다.
- 모션 감소 설정과 터치 입력에서는 커스텀 모션·커서를 강제하지 않는다.
- 후속 조정에서 위치 전환을 제거해 포인터 좌표를 즉시 반영하고, 내부 커서만 이동 방향에 따라 ±14도 흔들린 뒤 복귀하도록 분리했다.
- 중앙 기본 박스의 native cursor 우선순위를 제거하고 커서 라벨과 테두리를 확대했다.
- 최종 조정에서 화살표를 `/start-cursor.svg` 네이티브 CSS 커서로 분리하고 DOM에는 라벨만 남겼다.
- 시작 화면 전체의 중앙 박스·버튼 cursor 선언을 네이티브 화살표로 강제해 기본·클릭 커서 중복을 제거했다.
- 포털로 렌더링되는 팝업도 시작 페이지가 열려 있는 동안 같은 네이티브 화살표를 사용하되, 팝업에는 호버 문구 추적을 적용하지 않는다.
- 메인 박스 위치 편집 도구를 박스판 가까이 24px 내려 고정 Header와 겹치지 않게 했다.
